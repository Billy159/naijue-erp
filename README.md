# 奈爵 ERP 干净重写：阶段实现与验证边界

本目录是全新、独立的云端工程，不覆盖旧 Demo 或旧工程。当前已有领域、销货命令与持久化适配、精确金额规则和库存合成预览，不是已完成或可上线的 ERP。

## 当前完成

- 普通 TypeScript 领域/应用模块，React、Fastify、pg 为常规适配层依赖，没有另造前后端框架。
- 客户/供应商独立身份与行模型；商品统一价格位置；商品/颜色/版型/尺码四维 SKU；历史条码保留原字符串并直接绑定正式 SKU，冲突拒绝。
- 销售/退货/换货共用单头/实际行/收退事实，独立同仓，不需要原销售单或原行关联。
- 已保存未审核、审核、弃审、作废的应用编排，版本保护、原键幂等回执、追加库存效果、审计与事务端口。保存不改库存；审核收退必须精确配平；负库存不截零。
- 仅已审核单据参与收退统计。弃审退出统计、重新审核再进入；不是账户余额计算。
- 前端按动作加载及读取生命周期基础：未点击不执行、乱序响应隔离、关闭/切账号失效、保留已执行筛选和成功结果、旧详情不覆盖新版本。详见 apps/web/README.md。

## 运行验证

已用 Node 24.19.0、npm 11.9.0、TypeScript 5.9.2 在云端验证。依赖使用已有安装的软链接复用路径，未下载或重装大套依赖；node_modules 不提交。

有已安装的匹配依赖时，直接运行 npm run check。首次独立安装可按 package-lock.json 使用标准 npm ci（该独立安装在本轮未执行）。不要把其他项目的 node_modules 软链接挂上后运行 install：npm 即使指定 --package-lock-only 仍可能重写被复用目录的隐藏锁元数据。本轮观察到这项行为，已记录在 evidence/local-dependency-reuse.json。

检查命令：

- npm run typecheck：整个工程及测试的严格静态类型检查。
- npm run build：生成普通 JS 与类型声明，输出 dist，不启动服务。
- npm test：Node 内置测试运行器，全部使用合成数据。
- npm run check:dependencies：核对锁文件、清单与实际复用版本，不安装。
- npm run smoke:build：导入编译后的模块并检验基础算术，不连接数据库。
- npm run check：依次运行上述适用检查。完整输出见 evidence/check-final.log。

没有配置独立 ESLint 阶段，不把 TypeScript 检查称作 lint；没有执行浏览器验收、真实 PostgreSQL 事务验收或性能验收。

## 结构

- packages/domain：精确值、正规范目录、单据/库存关系型行合同、条码校验、调拨纯计划。
- packages/application：业务命令编排、事务/授权/规则端口、幂等摘要和单据收退统计。
- apps/web：前端按需加载、库存查询合成预览、复用选择器/分页和 DOM 检查；没有真实业务 API 接线或完整 Demo 视觉验收。
- apps/api：Fastify 销货命令和原请求回执 HTTP 插件，必须注入可信认证/业务策略；目前未监听端口。
- adapters/postgres：pg 事务适配器和版本化 SQL 迁移源码；尚未对真实 PostgreSQL 执行。
- tests/support：仅测试用的合成 copy-on-write 适配器、固定虚构身份和显式合成金额/符号规则，不是正式数据库。

## 不能误用的边界

1. SalesBusinessRules 必须由受信服务端注入。已实现精确半入折扣、最大余数分摊、独立退换有符号数量和收退配平等规则；必须提供可信商品价格事实，缺失不能猜零。算法核自既有源码证据，尚不等于冻结 Demo 运行验收。
2. 精确金额模块只提供整数 minor-unit 运算。十进制转换必须显式传尺度，额外精度拒绝；不是已冻结全部币种/价格/折扣政策。API 的正式金额格式仍需按有效合同落实。
3. SalesUnitOfWork 已有 PostgreSQL 适配实现源码。合成适配器、模拟驱动协议与 SQL 文本检查不能证明真实 PostgreSQL 锁、隔离、约束或并发行为。HTTP 输入校验已有实现；生产身份权限/引用策略和真实 PG 验证仍未完成，业务服务没有对外启用。
4. 当前切片只实现新运行时单据的普通审核/弃审循环。已批准的“切换当天核准库存作为起点，历史不重复影响库存，历史修改数量仅正确影响当前库存”需要独立的基线感知实现。本轮历史分支明确拒绝变更，避免直接逆不存在的旧过账或重复全量过账；不把此临时限制说成用户要历史永久只读。
5. 无真实资料、配置字典、价格或历史记录导入。所有测试标签和 UUID 都是显式虚构。实际尺码组按独立证据后续接入，不猜 S/M/L、颜色或季节配置。
6. 无计量单位、库存校正、资金账户余额、对账、赊欠/补收款；尺码组、尺码、季节只读端口没有维护操作。
7. 没有服务启动、数据库连接/执行、凭证生成、远程 push、部署或生产变更。
