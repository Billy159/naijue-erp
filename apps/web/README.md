# 库存查询首个交互切片（TEST ONLY）

已加入可看的最小菜单壳、库存状况表、复用候选选择器和商品分页器。它是重写中的第一个前端切片，不是整套 ERP 完工，也不是已接真实数据库的业务系统。

## 查看与验证

在仓库根目录运行：

```sh
node_modules/.bin/tsc --noEmit -p apps/web/tsconfig.json
node --test apps/web/src/inventory/model.test.ts
node apps/web/tests/run-dom-tests.mjs
node apps/web/build-preview.mjs
node apps/web/tests/run-bundle-smoke.mjs
```

构建只生成静态文件，不启动 HTTP 服务、不监听端口、不部署。当前离线环境实际有 esbuild 0.25.12 和 jsdom 29.1.1；这两个工具尚未列入根清单，干净安装的可复现性要由根依赖整合完成，不在此脚本自动安装。

- `dist-preview/inventory-preview-test-only.html`：可直接下载、用浏览器打开的单文件预览。为便于 file-open，代码/样式全部内嵌；它不是路由代码按需网络加载的证明。
- `dist-preview/index.html`、`main.js`、`main.css`、`inventory-route.js`、`inventory-route.css`、`synthetic-reader.js`、共享 chunks：拆分式构建，供获准的静态预览环境使用。启动只装壳样式；明确点菜单/合法 #inventory 深链才加载库存路由及样式，样式就绪再展示页面。没有 hover/空闲预取。
- `dist-preview/metafile.json`：构建导入图。esbuild 默认会把动态导入 CSS 也归入入口 CSS，脚本特意将入口 CSS 替换为仅壳样式，库存样式由叶节点工厂按点击加载。

## 当前已实现

- 注入式 `InventoryReader`，只读 `readInventory` / `readCandidates`，没有硬编码 API 地址、真实认证/业务记录、写请求或假后台成功。
- 进入库存页保持等待查询。商品/分类/仓库及高级供应商/版型/季节候选各自在打开时读取，20 项一页；搜索仅刷新已打开的候选，不刷新库存。关闭或离页释放读范围。
- 草稿与已执行筛选分开。查询显式执行；重置只改草稿；刷新、翻页/每页数沿已执行条件；查看范围不会贴上未执行的新条件。保留旧结果的加载/失败始终有明确标记。
- 100/200/500 款商品分页与跳页，DTO exact total 及完整筛选汇总独立返回。不全拉商品后在浏览器冒充服务端分页。 每页数切换成功前保留上次已执行档位；失败或取消后显示值与下一次显式查询一致，重试才明确重放失败请求的档位。
- product/color/fit/size 四维身份不合并。完整尺码标签（165/S、170/M 等）、组内顺序、尺码组及 FIT 独立列；不存在规格、数量未知、确定零及负数明确区分。数量以精确整数字符串展示，汇总不从可见 DOM 采集。
- 商品/颜色-FIT 折叠、颜色小计/商品合计显示设置。折叠不改变 DTO 总计；有效库存格传递明确 warehouse+sku 及完整规格回调，不存在规格没有动作。
- `LatestQuery` / `ReadScope` 控制读取消、较新执行替代旧执行、身份/权限变化清理。单页与候选各自持有短期读状态，不使用 localStorage。
- `preview/synthetic-reader.ts` 是显式 TEST ONLY 的隔离生成测试读取器。默认 3 款，提供已知负数、零、未知和不存在规格；103 款样本仅用于分页测试。它模拟服务端边界，不进入真实应用数据读取的默认分支。

# 加载基础层说明

以下是独立加载基础设施的原有边界。现在另有上方所述的库存首个交互切片；真实 API、数据库连接及冻结 Demo 运行/像素验收仍未完成。

## 已实现的边界

- `AsyncLeafRegistry`：只在明确调用 `load` 时执行路由、动作、页签或重能力的导入工厂。注册本身、未打开的叶节点和缓存淘汰均不触发加载。没有启动、hover、空闲或预测预取。
- 同一叶节点的在途代码/样式加载复用。必须的样式完成之后才交付模块；失败从注册表缓存移除，下一次明确动作可以重试。
- 不同消费者可以分别关闭，一个消费者离开不会取消另一个消费者仍在等待的代码加载。已关闭消费者不能接收迟到模块。
- `ReadContext` / `ReadScope`：绑定账号、会话代次、权限代次及路由实例/目标实体。关闭目标/离页时 dispose；换账号、退出、会话或权限变化时 replaceIdentity / clear，立即取消旧范围、清除其查询结果引用。
- `LatestQuery`：只有明确 `run` 才读取，编辑筛选草稿不会读取。执行条件被深复制并冻结；较新执行会 abort 旧读，并用序号阻止忽略取消的旧响应污染结果。
- 等待查询、加载、成功、失败、版本过旧、已释放分开。刷新失败/刷新中可保留上次成功事实，但它始终携带自己的已执行条件，不能贴上尚未执行的新筛选标题。
- 单实体可以通过 `versionOf` 维护已知版本下限。仅把已经成功的业务命令响应传给 `acceptAuthoritative`；旧详情读及之后返回的较低版本不能把状态回退。这不是写请求实现。

## 组合方式

1. 壳完成身份确认后建立 `ReadContext`。这些字段只用非秘密身份/版本标识，不得放密码、会话 token 或其他凭证。
2. 每个实际挂载路由/抽屉建立自己的 scope。详情目标更换要关闭旧 scope 并建立新 scope，不能在同一个版本比较器内混用多个实体。
3. 由真实用户动作或授权深链调用对应 `registry.load(key, scope)`。导入模块不得在顶层自行拉业务数据。对包含必要 CSS 的叶，样式工厂要等样式真正可用，不只是插入 link。
4. 在当前 scope 内建立必要的 `LatestQuery`，把真实读取函数作为 execute 注入。没有默认请求地址、预填假成功或静态业务数据回退。
5. UI 订阅 `subscribe` 并通过 `getSnapshot` 渲染当前状态。不能只凭某个历史 Promise 的返回值重新打开界面；挂载和渲染仍应检查 scope。React 可后续使用 `useSyncExternalStore` 对接这些方法，本阶段不绑定组件外观。
6. 把控制台错误上报接到 `onSubscriberError`；订阅者异常不能阻断账号清理。UI 自身应遵守纯渲染，不在订阅回调中发起重复业务动作。
7. 离页/关闭时 dispose scope，并清理该视图的观察器、快捷键、扫码和其他监听器。基础层只管理自身订阅/读请求，不能自动发现页面额外注册的资源。

## 有界性与刻意不实现的东西

- 每个查询只保留当前执行和最后一次成功结果，不积累全站查询、商品、库存、候选、历史或草稿。
- 注册表的 `maxRetainedEntries` 是调用方明确给定的已就绪模块引用 LRU 上限，不是经性能验收的生产预算。在途导入最多为有限注册表中的叶数量；不因一个消费者关闭就重复启动同一在途导入。
- 浏览器/ES 模块加载器可能永久保留已经导入的代码。LRU/clear 只释放本注册表已就绪引用，不宣称能卸载浏览器代码或限制整个进程内存。clear 保留在途去重直至完成，并默认不留存该结果；若完成前又有明确激活，则可再次按 LRU 留存。
- 没有业务数据共享缓存、请求参数去重、防抖、路由器、保存/审核命令、离页草稿确认、矩阵窗口化或持续轮询。这些需要真实页面/服务合同后再接入；不得用本基础层冒充其已完成。
- `execute` 的请求仍必须由服务端授权。前端隐藏菜单、scope 和序号防串结果，不代替权限校验、事务、幂等或数据库版本约束。
- `ReadScope` 和查询状态均为短期内存，无 localStorage。业务草稿、视图状态、密码表单和服务端事实仍需分别管理，不把它们塞进查询参数或模块工厂。
- 查询条件仅接受无环的普通对象/数组及有限数字、字符串、布尔、null、undefined。日期先转为明确字符串；金额、超大数量及版本不得随意转为浮点数。DTO 的完整性、exact total、未知库存与零库存的区分由真实读取合同提供。
- 读取 DTO 按不可变数据使用；基础层不会为大型结果再复制一份。单实体版本只能比较该实体的权威版本，不能拿列表里某一行版本当整页版本。
- 没有新增任何业务页或按钮，也没有计量单位、库存纠正、资金余额/对账、客户供应商合并或尺码组/季节维护入口。四维 SKU、商品统一定价及实际 165/S 配置应以最终业务域合同接入，本基础层不生成配置或假数据。
