# 图片颜色互换：写入合同补充 v4（待确认）

本次不新增表、字段或索引。它只涉及商品图片页一次保存中，两张已占用颜色的配图互换归属，例如红色图改蓝色、蓝色图改红色。

现有约束要求每商品每颜色只有一张配图，逐张更新会先冲突；现有写入守卫也禁止“同一图片ID先删除关系、再插入最终关系”。因此这个分支目前不能完成。不能用临时假颜色、临时角色或跳过审计处理。

拟只补充一个函数的图片删除分支：在同一事务中已有可信审计、审计前后都明确含同一图片ID的更新，允许先移除这几行关系，再写入准确的最终关系。它不是删除原图文件。

保持以下规则：

- 商品、图片ID、原创建时间及创建人保留，图片版本只加一次，商品根版本只加一次。
- 当前员工权限、原请求键、商品和图片版本校验、完整修改前后审计仍必需。
- 只允许准确匹配已准备审计的最终行；唯一颜色约束继续生效。
- 未重插、插错内容、重复最终颜色、错误身份或任何一步失败，整笔事务回滚，不留下半次互换或成功回执。
- 原图、旧替换文件及历史审计保留，不批量改旧数据；旧的未分类图片不补造类别。
- 其他图片删除、SKU、条码、付款分支保持现有规则。

实现后须做真实隔离数据库正反例：两图/多图循环成功且ID和历史不变；缺审计、错版本、错前值、未重插、错后值及重复颜色必须拒绝并回滚。源码、SQL或协议检查不能代替这些实测。目前仅有提案，未实施、未执行 SQL、未认定验收通过。

如需回退，先关闭循环写入口，再恢复原函数；已正确提交的新业务图片和审计继续保留，不能用旧数据库快照覆盖。
