# 库存流水预览接线（2026-10-30）

## 根因与修改范围

原预览 `sales-chain-fixture.mjs` 未声明 `/api/inventory/ledger/query`，请求退回不支持该路径的 synthetic transport，外层显示500。此次仅修测试预览：同一个已提交的 SyntheticStore，装配现有正式库存流水 HTTP plugin/application service，读取真实合成命令产生的 ledger 与 receipt；不生成假流水、期初余额或成功空表，不改变正式产品源码、数据库规则或UI。

新测试读取器保留精确整数、原始来源ID/操作ID、撤销关联，未知余额变动保持 UNKNOWN。移除会错误依赖当前单据仓库的历史读取校验，保留原历史行、SKU、单据身份关联。模拟时钟写入时即使用6位小数秒，不在读取时改写历史时间。

## 实际验证

- 原生RED：缺少接口路径复现。初版大数量用例先遭金额上限拒绝，已保留该失败；改用合法明确赠品/零价确认后，原业务命令成功，读取仍在原版本失败。
- 修改后原生6项针对性通过：真实空结果、4条已提交流水、超过JS安全整数的合法赠品数量与反向流水、分页/游标/条件筛选、非法参数/未知SKU/越权/停用拒绝、弃审后改仓和替换SKU仍可查原流水。
- 安装后的便携测试与原销货fixture/seed回归合计14/14，退出码0。
- 固定d125生产构建每个input/output hash核对后，真实有界前台浏览器5场景通过：总仓空结果、备货仓4条、销货类型1条、来源单号1条、关闭重开回4条。页面实际HTTP200，无pageerror/外部请求，保留trace与5截图；最终窗口可继续交互。
- 证据位于云端 `recovery/inventory-ledger-d125-prep/` 与 `recovery/inventory-ledger-visible-0230/`。前台标题明确“d125产物+库存流水预览修复·合成非PG”。

## 验证上限

这是合成内存预览接线与限定读取验证，不是实际PostgreSQL库存流水、全部ERP或生产验收。前台未执行新的真实数据库保存/审核操作；正式API是否存在独立缺陷仍需实际PG测试。不修改已交付阶段16的固定d125源码包，本项属于后续独立提交。
