# Native transfer list/detail read slice

This is an isolated source implementation, not an enabled service, complete transfer UI, or PostgreSQL-engine acceptance. It adds no schema/migration, imports, production data, credentials, writes, listener, eager/unrelated catalog hydration, or legacy projections. Existing transfer commands are unchanged.

## Evidence and contract

Read before implementation: approved frozen Demo summary `erp-rewrite-planning/demo-source-evidence/core-functions-source-report.txt` (transfer section), `architecture/clean-erp-candidate.md` sections 0.2/5, `architecture/core-database-design-discussion.md` section 5, `architecture/demo-source-alignment-addendum.md`, and the independently reviewed `transfer-runtime-review.md`. These planning artifacts are outside this repository. The implementation consumes native 0001/0004 reference/header/line relations and their current contracts; no old Demo storage path is used.

Confirmed list filter fields: inclusive start/end business dates, multiple statuses, multiple from-warehouses, multiple to-warehouses, and advanced document number. Frozen `transfer-golden.js:10,19–21` mounts status/from/to multiselects. The single current DTO uses required `statuses`, `fromWarehouseIds`, and `toWarehouseIds` arrays; empty arrays mean no restriction, each populated list is OR within its dimension, and dimensions intersect with one another and trusted authorization. Dates/number remain explicit nullable scalars. Old scalar `status`/`fromWarehouseId`/`toWarehouseId` filter keys are rejected, not aliased. Duplicate values are rejected; status arrays contain at most the three defined statuses and warehouse ID arrays at most 1000 canonical IDs. Query-string filters and extra keys are rejected. Dates must be real calendar dates and start must not exceed end. Number accepts 1–200 trimmed characters without controls, uses a literal case-insensitive substring through native `lower()`, and never treats `%`, `_`, backslash or quotes as SQL wildcards/code.

Unconfirmed Demo details remain disclosed, not guessed as business rules:

- The API requires explicit page/pageSize. Its technical page-size bound is any integer 1–200, page starts at 1, and page × size must be a safe integer. Frozen `transfer-golden.js` exposes 20/50/100/200 choices, but the technical API bound does not enforce only those UI choices. Frozen `transfer-current.js:72` sorts last-update descending then `x.id.localeCompare(y.id)` (the Demo ID is its displayed document number). Native SQL uses `updated_at DESC, number COLLATE "C" ASC, id ASC`: primary order matches, number is retained as secondary, and native ID breaks exact ties. Default-locale JavaScript ordering can differ from built-in deterministic C collation, especially for mixed-case/non-ASCII numbers; this is an explicit source departure, not claimed exact locale parity. No new collation or database setting is introduced.
- The frozen full source `transfer-current.js:72` uses case-insensitive `toLowerCase().includes()` for document number. This extension replaces the prior provisional case-sensitive native match with parameterized `strpos(lower(h.number), lower($q::text)) > 0`; percent, underscore and backslash remain literal, never LIKE wildcards. PostgreSQL lower() follows its existing database locale/Unicode rules, which can differ at Unicode edge cases from JavaScript lowercasing; exact browser-locale equivalence is not claimed. No extension, collation, index or setting is added. A suggestion endpoint remains outside this slice.
- This slice does not decide import-era historical visibility. The reserved CUTOFF_HISTORY marker remains readable through the supplied native facts, but this implements neither historical import, fabricated creation facts, nor historical editing/posting. The future approved historical grant facts must be reconciled separately.

## Trusted composition and authorization

`createTransferQueryHttpPlugin` requires a current trusted authentication provider plus explicit `TransferQueryDependencies` (authorization and snapshot reader). No default provider, request-selected actor, role, hall grant, or admin fallback exists. `TransferActor` contains verified account, current hall (or explicit null), and normalized role. Service captures immutable validated copies before awaiting authorization. Authorization is called anew on every list/detail/warehouse-reference request, and a cancellation after policy/reader completion prevents a stale service result.

`createSourceConfirmedTransferQueryAuthorization` is an explicitly selected source-confirmed policy, never installed implicitly: ADMIN/WAREHOUSE receive all; SALESPERSON needs an authoritative current hall and receives the union of source warehouse hall, destination warehouse hall, and immutable `created_hall_id` plus `created_role = SALESPERSON`. That last branch requires the existing non-null native creator-account FK and account→staff relation; it does not substitute the creator's current staff role/hall. Reads do not grant command permission. A later role/hall change uses the new actor and policy decision, while creation provenance stays on the header.

The generic trusted scope is a union of non-empty intersection clauses, with fixed fields for each endpoint hall/warehouse and creation account/hall/role. Empty scopes deny; empty/malformed/unknown clauses fail closed. Trusted composition, not a request, chooses the scope. The adapter revalidates and copies scope/filter values before connecting, applies scope before count/page/detail, and never treats a requested warehouse as an authorization grant. Missing and hidden targets produce the same DOCUMENT_NOT_FOUND result before fetching child rows.

## HTTP

Register the plugin normally, optionally under a Fastify prefix:

- POST `/transfers/query`: `{ filter: { startDate, endDate, statuses, fromWarehouseIds, toWarehouseIds, number }, page, pageSize }`.
- POST `/transfers/detail/query`: `{ transferId }`.
- POST `/transfers/warehouses/query`: `{ search, selectedIds, page, pageSize }`. Search is a required trimmed string of 0–200 characters without controls. `selectedIds` is a required unique bounded canonical-ID array. A nonempty selection requires empty search and performs selected-label lookup, not pinned inclusion in an unrelated search page. Both modes count/page the same authorized relation.

The routes are read-only POSTs for structured filter bodies, not commands. They use application/json, reject query strings, limit bodies to 65,536 bytes, and send no-store/no-cache. Request abort or premature response close invalidates the read. Known input/permission/not-found/too-large/aborted errors map to 400/403/404/413/408; unauthenticated is 401, unexpected trusted facts or SQL errors are redacted 500s. Generic media/JSON/body errors map to 415/400/413. No service listens on a port.

Exact totals and signed-bigint-backed positive transfer quantities are JSON decimal strings. Versions, page and page size remain safe JSON numbers. Every list summary requires `updatedAt` plus `totalQuantity`, an exact decimal-string sum of all current native line quantities for that document, including explicit zero when no current lines exist. SUM is not constrained to the per-line signed-bigint range and is never converted to a JS number. Historical category snapshots do not exist in this native schema: there is no invented category/tag field, current-category substitute or schema addition.

The detail shape is `{ document: { header, lines }, stockBasis, references, catalog }`. Lines are only current native actual rows, with formal SKU IDs and persisted product/code/color/fit/size/barcode snapshots unchanged, including leading-zero barcodes. Historical labels are never replaced with current catalog labels. Header source/destination/hall/creator/approver display names are current names read directly from native warehouse/hall/account→staff references. `catalog.skus` contains canonical `{ skuId, productId, productCode, productName, colorId, colorName, fitId, fitName, sizeId, sizeGroupId }` for every existing native SKU size within the distinct product/color/FIT tuples represented by actual current lines. This availability is identity-based and includes valid combinations with no document line; it excludes unrelated colors/FITs/products. It does not imply command eligibility or stock. `catalog.sizeGroups` contains `{ sizeGroupId, code, name, members: [{ sizeId, code, name, displayOrder }] }` with every current native group member, including unused sizes, ordered by the persisted signed-integer display order then size ID. Duplicate display labels/codes do not merge identities. No legacy multi-size alias projection is used. SKU sizes must belong to their product's full native group; inconsistent/missing identities fail closed rather than receiving guessed labels. The canonical current product/color/FIT labels are separate from, and never replace, each line's saved snapshot labels.

Warehouse references return `{ page, pageSize, exactTotal, items: [{ id, name, hallId, hallName, enabled, hallEnabled }] }`. The explicitly trusted `all` scope can list every native warehouse, including unused and disabled rows. A restricted scope can list only source/destination endpoints of documents satisfying the identical complete whole-clause authorization union used by document reads. In particular, creator-account/hall/role authorization is not decomposed into broad warehouse catalog permission. `selectedIds` intersects that authorized relation and can never create a grant. Search is a literal case-sensitive substring of warehouse or hall name, not SQL wildcard syntax; stable page order is warehouse name then ID. Disabled flags are informational and are not filtered out. This endpoint is solely for existing-document filtering, never a transfer command eligibility source.

No login name, password hash, request hash, audit JSON, current stock balance or unrelated catalog data is returned.

## PostgreSQL protocol

`PostgresTransferQueryReader` accepts an injected pg-compatible pool and does not connect at construction. Each invocation acquires one client and executes one read-only REPEATABLE READ transaction:

- List: exact scoped COUNT, one scoped server-side page with the same native reference joins and deterministic ordering, then at most one page-batched aggregate over current lines for the returned native document IDs. The aggregate uses parameterized `unnest` plus LEFT JOIN/SUM and includes zero-line documents, with no per-document query, correlated aggregate, all-document hydration or in-memory paging. An empty/out-of-range page retains exact count and skips the aggregate.
- Detail: one scoped header/reference query, then one ordered current-line query with LIMIT 2001. The technical 2000-current-line response bound rejects overflow with TRANSFER_READ_TOO_LARGE, never silently truncates. After ownership/identity/position/quantity/snapshot checks, nonempty lines use two set queries: bounded native SKU availability for only actual-line product/color/FIT tuples (LIMIT 20001), then full referenced size-group membership (LIMIT 20001). Each 20000-row technical metadata cap rejects overflow with TRANSFER_READ_TOO_LARGE; no partial matrix or group is returned. An empty document skips both metadata queries. All four data reads share the snapshot; there is no per-line/group query.
- Warehouse references: one exact count and one bounded page over precisely the same authorized native warehouse relation. Restrictive authorization is an EXISTS subquery over complete transfer relations and whole scope clauses, with the candidate warehouse constrained to either endpoint. IDs/search/limits are parameters; no enabled-state/selected-ID shortcut grants access.

Every filter, scope, target, limit and offset is a driver parameter; only fixed internal columns enter SQL. Disabled references are not silently filtered out of historical/native reads. SQL failures or cancellation stop subsequent work and request rollback. Failed BEGIN/unknown COMMIT results discard the client; rollback failure surfaces both errors and discards it. Unknown commit is never automatically retried. Signal checks cannot cancel a SQL statement already in flight and do not claim pg driver cancellation.
