## Role and credential boundary

Three approved fixed NOLOGIN roles receive finite rights: initializer; importer; ordinary runtime. None owns the database/schema, bypasses RLS, creates objects/roles, controls triggers, or gains membership. Importer and initializer have no native/source/audit/stock table DML. Public execution is revoked on every new routine. The private common dispatcher, source-record proof, operation-closure assertion and identity helper are not directly executable by these roles. Finite definer entrypoints invoke them as owner while retaining the protected original SET ROLE identity. Runtime receives only pure key ID, ready boolean, role-fenced row-intent boolean, and publication-fenced inventory admission proof helpers. Before activation a non-importer key proof returns only UNKNOWN, never inactive quantity/source metadata; runtime row intent returns false before any source lookup.

`standard_import_identity` checks PostgreSQL's protected built-in SET ROLE identity, catalog attributes, and actual session membership. It does not trust a JSON actor, a custom GUC, a boolean, or a client claim. Importer commands additionally authenticate a canonical private 43-character raw session token against actual auth_session/user_account/staff, current ADMIN status, auth version, expiry and revocation. Shared locks fence session/account/staff changes without conflicting with the ordinary UOW's identity-share locks. Existing current account login uses the real Node scrypt/session codec. Initial account provisioning accepts the encoded scrypt value as a **separate private SQL parameter**, never a package field/audit field/result. It creates a current technical administrator, not an invented historical creator. Package original account references cannot silently resolve to that administrator.

An admin-authenticated controller followed by SET ROLE proves current-role object grants/denials only: `SET_ROLE_ONLY_NOT_NONOWNER_LOGIN`. It is **not** evidence of a low-privilege LOGIN session or escalation isolation. A production LOGIN profile requires separately demonstrated capability; no v26 cast or synthetic proof is issued here.

## Finite wire protocol

All commands use closed JSON keys:

```text
{protocol:'STANDARD_IMPORT_SQL_V1', operation_id, request_key, batch_id,
 plan_sha256, package_manifest_sha256, namespace, cutoff_at, payload}
```

UUID/hash/time fields have their actual types/format checks; numeric source money/quantity values remain exact canonical strings. SQL rejects numeric JSON values and noncanonical bigint/two-decimal inputs before native typmod coercion can silently round them. Mandatory wrapper identity-basis fields reject missing/JSON-null through explicit NULL-aware predicates. The SQL receipt request hash is SHA256 of phase plus PostgreSQL JSONB text (initialization also binds its separate private encoded credential). It is not the client's typed requestHash. Original source hashes similarly use PostgreSQL JSONB text of `{source_key,fields,source_refs}`. No token or credential is copied into a request/audit/result/error.

## Atomic sequence, publication and recovery

Each call is one API call per read-committed transaction; the server rejects other isolation levels so status cannot mistake a stale repeatable snapshot for acknowledged absence. The server rejects a second distinct new standard operation in the same transaction by real receipt xmin/current transaction proof, after allowing exact-original committed replay; this is not merely a client promise. The API obtains the common cutoff lock then actual actor/original-key lock, validates the original receipt before any new DML, and uses exact batch sequence CAS. Before returning, **SET CONSTRAINTS ALL IMMEDIATE** runs every real retained deferred validator under the finite SECURITY DEFINER API owner, then restores deferred mode. Mutation reply COMMITTED is a candidate until the outer client receives COMMIT acknowledgment; it is not early durable success. No validator/trigger is disabled; this closes execute-only caller ACL/RLS reads without granting raw import table access or changing old validator security attributes.

No imported USER_ACCOUNT lane exists. Initializer/importer finite definer paths alone see prepared source/native facts for closure. UNKNOWN and generic unproved absence are denied. Later cycles use real APPROVE/reversal entries.

Command/replay reply is exactly `{protocol,operation_id,batch_id,request_sha256,state:'COMMITTED',sequence,cursor,receipt}`. Sequence/cursor are the **original committed operation checkpoint**, not later batch progress. Receipt.status is the separate batch lifecycle. Status uses the same cutoff/original-key lock barrier; ABSENT reply has null request_sha256/sequence/cursor/receipt. UNKNOWN transport outcome never authorizes a new key or blind replay: quarantine/close the original client, query the exact original key through the lock barrier, and resume only that same request after acknowledged absence. Same-key changed requests fail IDEMPOTENCY_CONFLICT; committed originals return the original receipt and do not repeat DML.

Inspect returns exactly protocol/system_identifier/database_oid/database_name/catalog_sha256/current_user/session_user/role_mode/proof_scope. Birth IDs are JSON strings. Catalog digest includes actual routine bodies/owners/ACLs, relation RLS/ACLs, constraints and policies; current_user inside the definer is not a nonowner LOGIN proof.
