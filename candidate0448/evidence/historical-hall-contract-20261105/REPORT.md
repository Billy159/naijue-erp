## Implemented

- Historical sales hall is nullable through domain/application data, PostgreSQL codecs, saved-document preparation, query/list DTOs and API input. New business documents still require a valid hall and same-hall enabled warehouse.

An explicitly selected, authenticated warehouse observation can produce MIGRATION_DERIVED, with original hall remaining null in source evidence. The approval reader requires independently pinned bytes, source namespace/hash/row references, unique target and source IDs, and an opaque verified identity. Size/row bounds are 64 MiB / 250,000 records.
- The source-header mapper keeps both raw and normalized source fields unchanged. Its separately authorized capture resolver prevents an input row from self-authorizing a derivation. The older normalized-field-mutating businessHallOverlay entry point is explicitly retired.
- Ordinary/stream envelope and required new source-profile integration was performed by the amount worker, with the frozen hall contract. Its execution path remains explicitly offline until the separately reviewed successor is admitted.
- Three streaming CLI entry points accept paired --historical-hall-approval and --historical-hall-approval-sha256 arguments. Approval files must be outside the package. Public stdout exposes only the approval hash and count, not its full UTF-8 source bundle.
- Historical null/cross-hall command exceptions require the original same-transaction sealed migration header, not a CUTOFF_HISTORY label alone. The original pair must remain unchanged for that exception. A user can change current hall/warehouse under the normal current-reference and authorization rules; the old capture is not changed.
- Readback separates historicalHallEvidence from historicalHallDiffersFromCurrent. The current header remains current business state. Original capture is never refreshed from current warehouse/staff tables. Ordinary list proof reads are batched after authorization and pagination, using immutable import_record pointers to locate exact chunk operation IDs before expanding their import audits and committed receipts. No new grants or security-definer routines were introduced. Legacy typed-history provenance is read from its preserved field_provenance.
- Hall-scoped permissions still compare the actual current document hall. A null hall does not gain salesperson access through a warehouse/actor fallback.
