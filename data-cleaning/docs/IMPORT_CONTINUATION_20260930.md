## 后续整批接收与独立建库流程

1. 接收本批完整文件夹，保存原件副本、逐文件哈希、结构合同、裁定及其原始尺码 / 条码对照表副本。工作表、表头、缺文件或新文件变化先列出。货品编码、颜色编码、尺码编码、条码按原始文本保留前导零。
2. 清洗本批业务行，按来源身份复用现有档案 / SKU及已确认裁定；生成与旧批完全重复、同单号变更、新增及例外清单。既有其他入库/出库转成调拨后，与直接调拨导出的原单号关系必须去重，不能三份来源各算一张。
3. 复用货品、分类、仓库、颜色、尺码及逐SKU裁定。已定稿历史条码按精确登记值匹配；新增或缺码商品按其方案使用完整存货默认条码作商品段。源身份变化、未知规格和重码单独报告，不将旧白名单套到不同规格。
4. 本批完整全仓库存经确认后作新库数量期初，共同截止时点之前的历史记录留作查询，不叠加库存。截止之后未被期初覆盖的有效业务才增减，未审核单不生效。旧批131张盘盈盘亏成因仍记录未查明；本批原记录保留，不伪造作废。打印日期不当作库存业务截止时点。
5. 在独立空数据库事务导入，重复执行不得重复写入或叠加库存。回读本批档案、单据、明细、各仓各SKU数量及精确条码绑定，保存报告和备份，当前业务库不作为新批试验库。

现有清洗映射、条码固定清单、事务命令和重复迁移校验可复用。已实现的接收入口可更换文件夹路径，保存批次、结构差异和裁定；遇到新增档案或来源格式变化时需补映射。

**当前是“整批接收已实现”，不是“任意文件夹自动清洗建库已验收”。** 历史原导入入口现归档为 `data-cleaning/import/import-tplus.ts`，只接受已有规则形成并通过预检的数据包，显式补充初始化只重放已确认条码清单。下一批须据实际文件形成预检和新库导入入口，并对该批验证；不能把接收成功或历史批次复跑成功当成新批数据已正确。
