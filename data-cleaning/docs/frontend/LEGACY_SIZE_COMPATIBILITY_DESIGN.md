# 新尺码体系与历史尺码兼容层 · 前端方案

状态：前端表达与兼容边界设计，待人工验收；不属于正式业务基线或数据库迁移方案。

## 本次依据

原表：`T+数据/枚举档案/尺码.xlsx`，工作表“尺码”，A1:C241。

实读结果：240条；字段为编码、名称、停用。编码全部是文本，10条两位码、230条三位码。编码与名称各自无重复，本样本停用值均为0。`01`完整保留，`202`对应`165/S`。源文件未修改，前端快照逐行保留原编码、名称、停用值与来源行。

原表没有历史尺码组、商品、SKU或条码关系；这些关系不可按前缀、名称或排序推断。现有M260xx全部是之前的虚构商品样本，不把它们伪装成T+迁移商品。

## 页面表达

1. 商品设置 → 尺码组：默认仍是五套新商品标准组；无尺码保留在上衣组。
2. 同一页“历史尺码资料”：只读弹窗，名称/编码搜索，30条分页；原名称、原始编码、原组（未提供）、原状态、历史尺码标识。
3. 新商品选择器只显示标准组，240条历史资料不进入日常选择器。新组条码编码仍须明确配置，不因名称相同而自动取历史码。
4. 将来接入的历史商品在颜色尺码Tab显示“历史尺码”、原尺码组和原名称/原编码列表；不出现转组或重新映射入口。当前已有这条渲染分支，但没有编造历史商品填充进去。
5. 商品条码Tab显示当前码、来源方案、历史记录。缺失日期/方案显示未记录。方案切换不重写绑定；生成后仅为新码记录本次方案与时间。

## 前端数据区分

| 字段 | 用途 | 处理方式 |
|---|---|---|
| sizeSystem | standard / legacy | 标准和历史分支明确分开 |
| size.id | 规格引用的内部身份 | 与显示名称、条码编码分离，禁止按名称替换 |
| size.name | 尺码显示名称 | 历史值原样展示 |
| size.code | 条码尺码编码 | 字符串，保留01等前导零，不转数字 |
| groupId / legacyGroupName | 所属组 | 真实历史组缺失保持空，不按码段拼组 |
| isLegacy | 历史资料标识 | 原始快照记录为true |
| legacySizeRecords | 某历史商品原有尺码引用快照 | 必须来自商品/SKU关系资料，不由枚举表生成 |
| sizeIds / colorIds / barcodes | 原规格和条码引用 | 保留原关系；新标准组变化不能改写它们 |
| currentMeta / historyMeta | 条码来源方案及记录时间 | 有记录才显示，不用当前方案倒填旧码来源 |
| sourceHash / sourceRow | 取证与回读 | 定位本次原始文件版本和行 |

前端历史表的`legacy:tplus:size:row:N`仅为本次不可变文件快照的行标识，须与sourceHash一起解释；不是旧ERP主键，也不是新生成的条码码值。未来接入真实旧ERP主键时单独保存原主键，不用本次行标识覆盖它。

## 兼容方式

- 原始枚举快照与标准组分别存储，快照冻结只读，不做自动映射表。
- `sizeRecords(product)`按商品所属体系读取尺码。旧商品使用原引用快照；新商品使用标准组；名称相同不等于身份相同。
- 已明确绑定的当前/历史条码继续优先定位同一个既有规格。兼容解析仅在该商品原有尺码引用内比较原码，不在240条全表按名称猜规格。
- 商品准备过程遇到legacy分支直接保留已有规格，不再次执行颜色×新标准组。
- 历史商品保存拒绝原尺码记录、组及规格关系的修改；缺失条码仅允许补到已经存在的绑定项，不补造完整笛卡尔积。
- 生成条码仍要满足当前方案的货号、颜色、尺码和其他必需字段。原码长度不适合所选方案时阻止生成；不截短、补零、转换或覆盖旧码。
- 标准组编码未确认时保持空白，不能把历史202自动赋给新组的165/S。
