# ERP V2 · UI Foundation

此文件记录本轮视觉实现，不是业务需求基线。主设计使用 backend-system-generator；Taste 仅参与视觉 Review。保持浅色单主题。用户的纯色蓝、紧凑 ERP 指令优先于 Skill 的渐变和默认宽松尺寸。

## 实现边界

- ui-tokens.css：唯一色彩、字级、间距、尺寸与字体入口；沿用 Skill 的 ca 语义 Token 契约，保留旧模板别名。
- styles.css：全局外壳、Page Header、按钮、表单、Tabs、表格、状态、Drawer、Side Panel、Tooltip、分页、空态与 Sticky 操作基础。
- gold.css：矩阵固定列、分组 Sticky、录入表以及原有详情的布局适配；没有 gold-mode 页面字号覆盖。
- index.html：统一加载三层样式，二级导航移除装饰图标，名称和顺序不变。
- gold.js：只有两处行内像素列宽改为尺码列数变量，交互与数据计算不变。
- 旧样式与脚本快照保留于 ui-foundation-before；旧 sample-base.css 不再进入当前样式链。

## 原内容映射与页面应用

导航名称与顺序、商品筛选及八列表格、商品详情四个 Tab 与字段、库存查询条件与商品/颜色/仓库/尺码结构、库存流水、调拨列表/开单 Tab、扫码/明细/原有底部操作全部保持在原有位置与入口。

商品：去除大字号覆盖，列表、详情表单、图片占位、价格、Tab 与其他页统一。库存：压缩分组标题、行高、识别列与尺码列最小宽度；保留原折叠与 Sticky，折叠容器不再强制最小高度。调拨：单据头、扫码框、编辑格与操作条共用视觉规则；不改变操作所在区域。

## Taste Review 与验证

纯视觉 Review 检查了商品列表/详情、库存结果/流水 Drawer、调拨录入工作区。修正：

1. 分页预留垂直空间，避免库存结果高度挤走分页。
2. 可编辑格增加轻边框，避免空数量格难以发现。
3. 普通导航 Hover 排除已选项，防止掠过当前菜单时冲淡 Active。
4. 共用行内小按钮，避免标准按钮撑高商品表数据行。
5. 表单 Focus 缩为清楚的细线，减少扫码输入框双重边框的视觉重量。

主按钮白字对比度 6.84:1；主文本 12.75:1；次文本 6.20:1；占位文本 5.03:1；选中文字 5.56:1；错误文字 5.61:1。禁用控件不作为正常文本对比度承诺。

30 项既有 DOM 交互回归通过。实际浏览器检查了宽桌面、笔记本和窄窗口布局；窄窗口表格保持横向可达，不删字段。库存数据行从 39 缩为 28，字大小仍为 13；分组标题从约 40 缩为 30。实际预览已确认同屏库存增加，未将不稳定的窗口截图尺寸包装成精确行数提升百分比。

四份正式需求文档以及 model.js、engine.js、app.js 与本轮前快照逐字节一致；验证结果见 ui-foundation-verification.json。未新增后端、业务状态、字段、导航模块或持久化。
