# ERP V2 · 页面结构体验原型

本轮状态：待用户体验和确认。只做前端结构验证，使用已选择的深海蓝，不再比较颜色。

## 页面入口

当前静态预览服务器地址：

- 商品信息：http://127.0.0.1:8767/#products
- 商品详情：商品列表点击 M26001 或“查看详情”。
- 库存状况：http://127.0.0.1:8767/#inventory
- 调拨矩阵：http://127.0.0.1:8767/#transfer

库存页顶部可切换“汇总库存 / 分仓对比”，并多选总仓、网点仓、温州仓、备货仓。

## 启动与停止

最简单：打开同目录 `index.html`。该原型不依赖网络接口，无需安装依赖或构建；脚本和样式均在同目录。

如果使用本地预览地址：双击同目录 `start.command`，或在终端执行：

```sh
cd '/Users/billy/Desktop/Workspace/project-007-业务管理系统/outputs/ERP-V2-Demo-V1/ui-structure-prototype'
python3 -m http.server 8767 --bind 127.0.0.1
```

保持终端窗口打开，浏览器访问 http://127.0.0.1:8767/ 。停止服务器按 Control+C。如果端口已被本原型使用，直接访问现有入口即可；如果是其他程序占用，可将端口改成 8768，并使用对应地址。

这是只提供 HTML/CSS/JS 文件的本地静态服务器，不是真实业务后端。仅绑定本机地址，没有部署到公网。

## 建议体验顺序

1. 商品信息：确认 M26001 一款一行；按款号/名称、分类或启停状态查询。
2. 打开商品详情：依次切换基础资料、规格、条码、库存。测试大抽屉的可读性、关闭后返回列表的连续性。
3. 在基础资料修改名称或默认售价，再点“保存档案演示”，观察列表更新。切换 Tab 保留尚未提交的表单输入；关闭前需保存演示，刷新全部恢复。
4. 详情库存 Tab 先看四仓概览，再点“进入库存状况”。
5. 库存状况选 M26001，只勾总仓：藏青 39、白色 38，总计 77；列合计 M19、L32、XL20、2XL6。
6. 勾选三仓，比较汇总与分仓模式。三仓合计 120；全选四仓合计 124。查看备货仓藏青 XL 的 -1，点击数字可看到来源说明。
7. 切换 M26004，选择四仓。它有 8 色、6 码，展开 40 行（32 行仓库明细＋8 行颜色小计），再体验颜色折叠、单色筛选、横向与纵向滚动。
8. 调拨矩阵：总仓 → 网点仓，藏青 L 默认录入 4。给现存 0 的藏青 2XL 填 2，查看不足提示和明细。库存不足不禁止预览；小数、负数量、同仓则明确标错。

## 哪些交互已实现

- 页面导航与当前模块的完整浅蓝选中色块、3px 主色线、深主色图标与加粗文字。
- 商品搜索、分类筛选、启停筛选、空结果、重置；一款一行。
- 商品详情模态大抽屉、四个 Tab、关闭、基础档案的内存编辑；Tab 可用方向键切换，关闭可用 Esc。
- 独立库存查询页：商品切换、仓库复选、全选/清空、颜色筛选、汇总/分仓切换。
- 颜色分组单独折叠、全部折叠/展开；折叠保留小计。表头、颜色列固定，分仓对比额外固定仓库列。
- 所选仓按规格实时相加；行、列、总计联动。未选仓库显示未选择，不伪装成库存 0。
- 负库存显示原数和警告文字；汇总可能抵消负数，范围提示仍保留“含负库存规格”。点击数字显示组成仓库/规格。
- 调拨矩阵数量输入、规格数与总量汇总、不足提示、预计调出后数量、明细预览、会话内草稿演示。
- 切换调出仓保留本款数量并重新核对不足；切换商品会清空当前数量，以免带入其他规格。

## 哪些是 Demo

所有商品、仓库、规格、库存、价格、条码字符串及调拨内容均为虚构示例，不是待导入的正式 Demo 资料。条码页明确标注未核验，不支持实际扫码或打印。

原型没有登录、权限、真实后端、数据库、库存流水或审核生效。保存档案只更新 JavaScript 内存；保存草稿也只是当前会话的数据快照。不会增减库存，刷新恢复初始数据；没有 localStorage、IndexedDB 或持久化接口。

调拨明细中的“预计调出后”只为数值演示，不表示已审核。没有实现跨商品完整开单、真实弃审或其他业务模块。侧栏其他菜单仅保留顺序与文字，标明本轮未制作，不提供假功能。

## 当前结构判断，等待用户验证

[INFERRED|MED] 商品详情用大抽屉＋四个 Tab 是本轮建议：频繁开关不同商品时能保留主列表上下文。基础资料可编辑，规格/条码只读查看，库存仅做分仓概览。高频颜色尺码和多仓查询放到独立库存状况，避免详情抽屉越来越拥挤。抽屉是否足够宽、是否需要独立详情页，应体验后决定。

[COMPUTED|HIGH] M26001 两色三仓为 8 行（含小计），按 44px 约 352px；M26004 八色四仓为 40 行，约 1760px，超出一次可视范围。全部折叠后是 8 行颜色小计，约 352px。表头和总计另占高度。

[INFERRED|MED] 仓库子行适合少量仓库对照，但颜色×仓库数量相乘会拉长页面。建议先保留默认展开与用户手动折叠，让用户体验后决定是否改为“默认折叠、只展开当前颜色”。不要先增加复杂分页或减少字号。

请重点判断：

- 商品详情用大抽屉是否合适，还是更想要独立详情页面？
- 商品主列表只保留全仓总库存，是否足够？
- 分仓模式默认全部展开，还是默认折叠更便于日常查货？
- 经常比较的仓库通常是 2 个、3 个还是更多？是否应保存常用仓库组合？本轮未持久化偏好。
- 长表内部滚动与固定列是否自然，是否更喜欢页面整体滚动？
- 单色筛选、折叠小计是否足以控制长度，是否确有需要再做分页或颜色切换？
- 年龄偏大的实际仓库人员能否辨认查询数字、负库存和调拨输入？本轮没有真人可用性测试。
