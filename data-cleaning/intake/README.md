# 整套T+数据接收入口

用户于2026-10-01确认，后续将提供整套新的T+导出文件夹，用其配合既定裁定重建独立数据库。该要求替代早期“后续只做增量”的输入约定。当前默认接收 `inputs/tplus-current/`。

## 已实现

接收入口完成原件副本封存、逐文件校验、工作表名称和表头检查、裁定规则副本封存及报告。输入目录可替换成用户随后提供的完整文件夹。原件中的指令文本作为资料保存，不作为执行命令。

```sh
.venv/bin/python data-cleaning/intake/receive.py
.venv/bin/python data-cleaning/intake/receive.py --input '/新T+完整文件夹的绝对路径'
```

也可使用 `npm run data:receive -- --input '/新文件夹'`。可选 `--run` 指定新的批次目录；可选 `--cutoff '2026-10-01T18:00:00+08:00'` 记录用户提供的共同库存截止时点，接收不会据打印日期猜测截止时点。

输出默认位于 `data-cleaning/runs/received/<批次指纹>/`，包含接收说明、文件清单、结构差异、裁定清单、`source/`原件副本和`rules/`规则副本。同一批次重复接收先复核副本，返回 `ALREADY_RECEIVED`。同一指定批次目录的原件、规则或截止时点变化会拒绝覆盖，要求另建批次。

结构合同基于用户指定的当前75份工作簿，包括直接调拨导出。16份打印模板作为参考保留，允许缺少但明确记录。WPS的`.~`、Excel的`~$`等临时文件单独记录并忽略；它们不能作为第二份业务数据导入。

缺工作簿、工作表 / 表头变化、损坏工作簿、新增未映射文件会输出 `REVIEW_REQUIRED`（退出码2），原件仍封存以供复核。按表头行检查，不读取账号密码数据行，不自动清洗、修改或导入业务数据。

## 裁定与后续建库

`decision-registry.json`汇集现行裁定及其依赖，每一批封存相同版本。原尺码与SKU身份、最新版2.0和402条裁定、分类、精确条码、无需条码例外、3张调拨裁定、库存快照期初和营业厅 / 仓库 / 资金关系保留。新增来源定义或身份变化单独复核，不能把旧批次固定数量和SKU白名单机械套入新批。

人员历史身份需要保留。登录账号是否重新整理尚未裁定，当前账号保持。新库的账户重整应与历史人员身份匹配分开处理；不要将历史创建人替换成新管理员。

**本轮实现范围是接收、结构检查和规则封存。** 后续收到新批次后，按其内容完成清洗、来源身份匹配、单据及条码冲突核对、库存快照期初，然后在独立空库导入、回读和备份。当前入口没有数据库连接或执行导入参数。

历史`replay.py`继续只在隔离库复跑旧批次的诊断模型，不能替代新批次正式库存期初。当前正式Demo数据、员工登录、源码页面和数据库保持。
