# 首个切片的有效业务方向

更新时间：2026-10-20。依据是本轮已确认字段方向、随后用户新决定和冻结 Demo 的定向源码报告；最新用户决定优先于仍带“讨论中/未实施”旧状态的设计文件。

- 客户、供应商独立表族；销货/调拨各自头行；库存流水与当前整数数量；收退只记录本单账户、方向、金额。
- 商品价格整款统一；SKU 没有可维护价格覆盖。具体价格栏目与复杂经济规则不在本切片猜测。
- RETURN 是共用 sales_header/sales_line 的新业务记录；SALE/RETURN/EXCHANGE 独立同仓；没有原销售单/行外键，也不要求原单累计退量/退款上限。
- 条码保留完整原字符串；多个已确认历史码可指同一个正式 SKU；一个码不跨 SKU 重绑，冲突失败，不重编原主码。
- 保存未审核不改库存；审核才生效；弃审追加逆效果且保留收退事实；仅已保存未审核可作废；已审核不能直接改数量/金额。
- 审核时收退金额必须配平。用户短暂提出未收清也审核后已经明确撤回；不得加入欠款、负实收、账户余额或后续补收工作流。
- 统计只含已审核单据；弃审退出、重新审核再进入。
- 导入采用切换当天核准的库存起点；历史单据不再重复影响库存。允许按批准路径修改历史数量/金额并留修改记录，数量变化同步当前库存，但此基线感知实现留给后续切片。
- 无计量单位、无库存校正；全角色尺码组/季节只读，不补种猜测字典。

设计输入文件：奈爵ERP_数据库表与字段清单_讨论版.txt、architecture/core-database-design-discussion.md、frontend-loading-discussion.md，以及 demo-source-evidence 下的冻结源码报告。这些输入描述业务/设计证据，不等于本工程已经执行过建表、导入、浏览器验收或部署。

正式经济规则、权限和 PostgreSQL 行为必须分别提供实现与验证。当前测试中示范符号与无折扣运算明确只用于合成样例，不是替代批准合同。
