# v11 修订：商品所属组内全尺码

本单已按主控最新人类裁决收窄。此前“全系统有效字典均可选”“商品组仅作默认展示”及对应跨组技术方案撤回，不继续作为实施或验收依据。旧稿及曾经的确认保留在 Git 历史，当前以本修订为准。

已明确、无需再次询问的规则：

- 先读取商品真实所属尺码组，再取得该组全部有效尺码。组内 XS、XL 即使尚无 SKU 也应能选择；不是只列已有 S/M/L。其他组的裤码不可混入；无尺码只有所属组包含时可选。
- 商品所属组是录入边界。前端候选、矩阵、准备及保存采用同一规则；后端保存时按真实商品归属和成员核验，不能只信请求中的组 ID。
- 切换商品更新对应范围，取消旧请求并阻止迟到结果污染。组缺失、读取失败、未知分别明确反馈，不回退成全系统尺码。
- 已有真实 SKU 复用原 ID、编号、条码和记录。历史单据及旧规格回显原样保留；历史兼容不能成为新增跨组录入入口，不删除、重编或改变库存身份。
- 真正缺少的组内规格，只按最终获批保存合同补建本单实际使用的项；查询、选项、准备草稿和取消均不创建。失败时与单据一起回滚，不预生成笛卡尔组合，不恢复停用项。
- SKU 四维身份仍为商品、颜色、版型及真实尺码 ID；不按组重复创建，不凭显示名称合并不同历史身份，其他资料和人员权限不放宽。

仍待完整保存合同确认的内容（本次组内方向纠正不构成以下事项的批准）：

1. 缺 SKU 的 SAVE 新输入分支、同事务解析/必要补建及其与原幂等、版本、未知提交恢复的准确合同。
2. 新补规格业务编号规则。旧稿提出 NJNEW- 加新 UUID 的38字符规则，目前仅为待确认建议，不可投入写入；旧编号始终保留。
3. 营业员仅本单目的受托补规格的权限、原 PRODUCT EDIT 版本/审计/回执及当前事务证明闭包。不得以管理员身份代替或开放通用商品编辑。
4. 手工输入的真实无 MAIN 规格是否及如何存真实空条码的依赖写合同；不得把读取失败、未知或缺 SKU 变为成功，扫码仍要求有效真实绑定。
5. 对应 SQL 函数、触发器、内核和前端输入接缝的收窄后完整差异。由原 D1 牵头汇总；保留商品组成员硬校验，不机械执行旧29文件清单或去掉库存成员校验。无需变更的实现原样保留。

尚未再次提出确认问题；待精确收窄合同完整后只确认剩余新写语义，不重复询问组内选择方向。未依赖它的组内字典、已知 SKU、未审核界面、冻结 Demo 直接迁移、独立验收和已授权实现修复继续。v10 原仓库触发器字段求值修复独立，不因本单暂停。
