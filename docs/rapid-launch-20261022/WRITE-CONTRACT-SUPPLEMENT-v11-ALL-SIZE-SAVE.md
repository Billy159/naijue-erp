# 全尺码录入：一次确认的推荐方案

建议确认以下一套规则，继续沿现有单据和商品内核实施，不要求用户选择技术路线。本稿是待确认合同，尚未改写入规则；现有真实 SKU、全字典及未审核界面继续使用。

商品原尺码组保留，作为默认展示组。新增和未审核销货、调拨可以输入完整有效字典中的尺码，包括无尺码。SKU 身份仍是“商品＋颜色＋版型＋真实尺码 ID”；同一个尺码 ID 出现在多个组时复用同一 SKU，不按组重复创建，也不按相同显示名称合并不同历史身份。

保存时先按真实四维身份找现有 SKU；已有则复用原 ID、原编码及原创建记录。确实缺少时，在这次 SAVE 的同一事务内补建，只增加当前单据实际使用的规格。查询、选组、准备草稿和取消操作均不建 SKU。停用 SKU 不自动恢复，商品、颜色、版型、人员、营业厅等原有效性和权限要求保持。

为新补规格采用明确的新系统编号：`NJNEW-` 加该新 SKU UUID 去横线后的 32 位小写字符，共 38 字符。例如这是“新系统补规格编号”，绝不称原 SKU 码，也不是条码。现有、导入和人工填写过的编号逐字保留；本规则不补造原始资料缺失的历史码。编号或四维唯一约束冲突时整笔保存失败并回滚，不猜号、换号或覆盖旧身份。用户正常录单无需再输入技术编号。

营业员只获得为自己当前已获准保存的单据补规格的受托权，不获得通用商品编辑、改价、换组、恢复、删除或借用管理员身份的权限。每个确有新增规格的商品仍生成一次真实 PRODUCT EDIT：商品版本加一，其他主档值不变，新增 SKU 为版本一，并有原审计、回执和创建操作绑定；与单据审计、回执同提交、同回滚。没有新增 SKU 时不额外增加商品版本或商品操作。

手工录入的真实 SKU 如果确实没有启用的 MAIN 条码，由同一事务读回确认后保存真实空条码；读取失败、缺 SKU 或资格未知仍报错。扫码继续要求真实有效、唯一的原条码绑定。原码不重算、不生成假主码；旧未改行保留当时快照，已经审核的单据保持只读，按原规则弃审后才可修改。

未审核单据重新打开时显示全尺码输入，同时保留每条实际明细的 SKU、价格、符号、单位及历史快照。商品规格页和库存投影覆盖“默认展示组成员＋该商品已有真实 SKU 尺码”，按真实尺码 ID 去重。没有 SKU 或没有资格的空格不伪装成库存零；原分仓、原 SKU 总量及过账守恒保持。

技术实现只扩展原两个 `/commands` 的 SAVE 输入，不新增公开 URL，不增加数据库表、列或编号序列。旧 `draft` 请求及其幂等哈希保持；新增互斥的完整 `proposal` 输入，让服务端解析真实规格、生成明细身份和快照。原单据请求键、版本检查、同事务失败回滚和库存规则继续执行。

同事务刚补建的规格不能冒充“先前已提交”的商品事实：先锁商品并核验原完整基线，再核本次实际追加的根版本、SKU 九字段、审计和回执，只让这次获准 SAVE 内部读取使用；提交后回到原完整维护链证明。其他未提交行、暂存数据及未知来源均不放行。
