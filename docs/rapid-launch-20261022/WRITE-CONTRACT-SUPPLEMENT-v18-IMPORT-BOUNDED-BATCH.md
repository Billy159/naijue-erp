## 需要批准的准确变化

1. 仅SKU导入及库存来源贡献暂存：最多100个完整SKU或完整库存组共用一个事务；每批最多200条原别名/贡献。一个SKU及其全部别名、一个库存组及其全部贡献不拆开。同原来源批次、命名空间、选择证明、目标及角色，不混批。
2. 原来每条单独提交；改后本批任一项失败整批回滚。例如第51项失败，本批前50项一起回滚，之前已提交的批次保留。批内不跳过、不部分提交、不自动退回单条重试。
3. 完整身份、来源、结构、角色和能力核验由每条两次改为每批两次，并在同连接、事务内、提交前增加第三次真实核验。每项原有字典、组成员、权限、来源、身份、版本、锁、唯一约束及触发器仍逐项执行；不加TTL缓存，不改数据库权限或关闭约束。
4. 辅助进度日志按批完整写入并同步，结束或异常时保留现场；数据库原source/alias/import_record及事务回执才是提交事实，不以日志补造成功。数据库WAL、同步提交及审计不改。

字节边界沿现有窗口能力控制，包括必要数组序列化开销；保留原单项合法性，不把原stock的4MiB+4096收紧成新业务限制，不截项、不丢成员。若实际完整项不能容纳，明确停止交主控，不静默拆分或换执行通道。
