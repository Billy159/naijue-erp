# 同一reviewed连接的工作组合同

宿主独占真实pg Client的创建和最终关闭，沿原physical factory及whole-host-session。D3借入宿主传入的同一个controlled对象，openClient是返回该对象的逻辑借用，配合borrowedClient=true。每组确认COMMIT或ROLLBACK后不逐组调用discard。COMMIT应答不确定、连接或wire状态不确定时，D3调用controlled.discard并结束本次run。controlled.discard沿原实现立即标failed/poisoned并关闭真实连接，不能作为普通组释放。宿主原finally负责唯一最终close，close本身保持幂等。

执行失败且确认ROLLBACK的run仍按D3原返回结束，连接由宿主finally收口。原wire guard对SQL错误后仅允许清理的行为保留，不能把一次ROLLBACK当作运输层错误已全部恢复。下一次显式resume重新经物理身份、source/model、controller、当前服务授权和同根输入准入取得新的reviewed连接。

新batch query guard在每个BEGIN重置该事务的inspected/submitted/completed状态，原步骤序号从锁定inspect的真实工作组first开始。inspect选取已经按原program完整输入验证的磁盘plan组，step逐请求累计该组原输入流，complete必须达到last并精确匹配原组流摘要。SET CONSTRAINTS/COMMIT只允许已完成组，或锁定读取后的无写入skip事务。执行中的实际xmin/time/角色由SQL及原wire状态共同验证。

每个run有一次磁盘plan完整性读取，按原production authority已绑定initializerSha256/stepsSha256核全部原请求，并保存每组摘要。之后逐组检查按组处理，不反复扫描成功前缀。D3协调层的成功skip仍可不读取其steps；这不代表宿主首次完整性校验没有磁盘读取。后续读取使用同一个SQLite只读快照对象，且wire提交内容仍需匹配已绑定组摘要。

首次prepared仍须原prepareFresh35Admin154Import的真实WeakMap授权对象。transactionMode或batchedPlan字段本身不授权。显式resume重建的prepared必须重新通过真实target/root/input及原plan完整性绑定，不能只将旧标记注册进WeakMap。该恢复准入与160函数catalog/physical factory仍在实施，本页不声称已接通。

已写候选文件是source/tools/unified-import/whole-host-session.mjs和fresh35-host-session.mjs。前者只为新的物理限定160 profile选三条批SQL，原profile允许集保持；后者在原production authority闭包中追加fresh35ProductionBatchedImportQueryGuard。两件只做过Node24语法检查，尚未运行真实连接。catalog与source装载接缝仍属D1，CLI/program/kernel/launcher继续归D3。
