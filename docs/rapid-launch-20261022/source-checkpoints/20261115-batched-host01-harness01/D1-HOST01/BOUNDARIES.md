首次程序保持原prepareFresh35Admin154Import注册的同一个对象。续跑对象要求genuine same-client admission、已认证新扩展authority，以及共享SQLite快照的整个原program摘要匹配。原输入initializer+私参摘要、所有原steps摘要、总数、7字段identity、13字段组descriptor和前驱链同时绑定。

## 多组与最终核账

同一reviewed借入client承载连续组事务。genuine production batch guard按每个BEGIN和锁定inspect选择已绑定工作组，检查原请求顺序及组流摘要，在complete之后才允许写事务COMMIT。读取已成功组的无写入事务可结束。未知提交必须真实discard并结束本run，下次显式resume新建经完整核验的物理连接。

整个run首次核一次磁盘plan完整性，之后逐组检查。D3协调层skip可以不读成功组steps，宿主首次完整性读取仍存在，不能报告成零磁盘读。实际共享plan是同一个readonly SQLite对象，CLI finally唯一close，operation不另open/close。

新连接最终reconcile保原准确standard_whole_package_verify_v2 SQL，只接受原initialize+私参绑定。该事务只执行核账并确认ROLLBACK，不作为写组，也不允许COMMIT。新genuine context/authority需重新绑定，不能将旧上下文对象缓存作为新连接证明。最终数量/金额/库存及来源事实仍由原reconcile和SQL verifier核账，源码检查不等于这些结果已通过。
