## 同设备峰值

设 `S` 是新增并持续占用的接收件、展开输入、审批附件及源码落地，`I` 是持久索引和 summary，`J` 是持久 batched plan、INIT 和报告。 `V0` 是当前已装 PGDATA 实占，`Vp` 和 `Vf` 是导入期间 PGDATA 高点与停库后定值，均含 WAL。 `C` 为完整新冷备，`U` 为额外独立恢复副本，`T阶段` 为该阶段同驻的额外临时占用。暂存片和合成件同时保留时都计入，硬链接按同设备和 inode 去重。

| 阶段 | 从当前可用量扣除的新增并存字节 | 对照估算 | 压力估算 |
| --- | --- | ---: | ---: |
| 接收和落地 | `S` | 3.00 GiB | 3.00 GiB |
| 建索引与准备 | `S + I + T准备` | 11.00 GiB | 11.00 GiB |
| 导入 | `S + I + J + (Vp − V0) + T导入` | 33.45 GiB | 84.93 GiB |
| 停库后新冷备 | `S + I + J + (Vf − V0) + C + T备份` | 41.97 GiB | 144.93 GiB |
| 保留源和冷备，再独立恢复 | `S + I + J + (Vf − V0) + C + U + T恢复` | 55.50 GiB | 209.93 GiB |

两种场景共用 `S=3 GiB`、`I=3 GiB`、`J=5 GiB`，阶段临时量按每阶段额外 5 GiB 计，并假定 `Vp=Vf+5 GiB`、`C=U=Vf+1 GiB`。这些是规划预留。对照场景的 `Vf` 取旧完整库实占 12.52 GiB，压力场景假设新库停库后达到 64 GiB。后者采用先前大批量整事务候选讨论过的高端预算量级，现用作独立压力假设。两种情况下最低根卷余量约 199.41 GiB 和 44.98 GiB，高于 28 GiB 分别约 171.41 GiB 和 16.98 GiB。旧库和原冷备已反映在基准可用量，未来新增的两个完整副本各自计入峰值。 [先前预算依据](../20261114-r3-mixed511234-full-carrier-local-01/REVIEW.md)

## 最终复核及扩容位置

用最终签准包补齐同驻接收件、完整附件、root06 物化和各自实际分配块，同版 index、summary、plan、INIT、scratch 和持久保留范围。写入前用最新同设备 (F) 与有效 PG/WAL 峰值预算核算。进入冷备前再用停库后的真实 PGDATA、WAL、媒体、配置、版本附件逐对象盘点。恢复前核落点设备、现有备份仍保留、额外恢复文件和恢复临时量。按 `max(0, 28 GiB + max(各阶段同设备新增并存字节) − F)` 得出当前根卷最低缺口。在上述同卷压力假设中，若只提高 `Vf`，约 69.66 GiB 即触及 28 GiB 保留线。

若最终缺口主要来自新冷备和恢复副本，可为两者配置可用的独立挂载卷，根卷继续满足自身 28 GiB 保留线；若 PGDATA、WAL 和必须留根卷的输入或 scratch 已超额，应增加承载 PGDATA 的 `/dev/md0p1` 根文件系统容量。两处路径位于同一设备时仍按同卷计。当前未配置第二卷，未创建备份或恢复副本，未启动或写入数据库。
