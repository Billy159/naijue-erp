# A1 release health/readiness contract

`health()` retains `/healthz` as HOST_ALIVE, exact build/commit identity, databaseChecked:false. Every call then issues a fresh `/readyz` against the same target, requiring 200/READY. The independent loopback activation check does the same. Stage, activation and boot still use the shared gate. HTTP body/time/retry bounds remain; no previous success is cached. No business acceptance is implied.

Dot-native offline evidence `../report-batch1/a1-{red,green}.log`: baseline rejected actual HOST_ALIVE and accepted stale HOST_READY; new 4 test groups pass, including direct/proxy targets, independent loopback, malformed/oversize/errors/timeouts, no stale success, and all boot consumers. AST-only extraction runs the actual embedded Node probe against closed HTTP doubles. No deployment script entrypoint, Docker, production network, or database was invoked by these tests.

IMPORTANT: `boot-entry.py`'s previously reviewed deployment SHA pins are deliberately unchanged. The edited deployment script is NOT re-approved by this patch and fails the old trusted-source hash gate. A new independent review/pin authorization is required before any release. This is an intentional release blocker, not permission to rewrite pins for green tests.
