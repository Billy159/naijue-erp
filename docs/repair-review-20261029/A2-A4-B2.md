# Bounded public probes, product reads, and safe diagnostics

## A2
Public /readyz now coalesces concurrent requests into one physical application readiness check, with 32 waiters and a 2-second logical deadline. There is no successful readiness cache. Aborted/timed-out work retains the physical slot until cleanup completes; late success cannot become a response. Client cancellation is propagated, and admission checks stop between issuer checks. An in-progress issuer verification is NOT interrupted by releasing its lease (which could revoke the issuer).

## A3
Product management reads have a 20-second total HTTP budget starting before authentication and checked again before/after serialization. Acquisition cancellation returns promptly and owns/discards any late connection; ordinary in-flight read SQL retires its lease exactly once. Current read authorization uses the same safe cancellation seam. Issuer verification is allowed to settle before its lease is released; HTTP waiting is still bounded. Authentication/issuer physical work remains bounded by existing driver/resource timeouts, not an invented cancellation guarantee.

Full matched-product/all-warehouse stock evidence is deliberately retained: unknown is not zero. The initial checkpoint quantified 1000/1001/2000/2001 additional SKU using 1000-row batches; the later bounded set-query change below supersedes that application transport path. Neither checkpoint is a PostgreSQL query plan, memory benchmark or measured P95. No schema/function change or stale authorization cache was introduced. Further set-based optimization requires actual plan/scale evidence.

## A4
Server-generated requestId is shared through private request/async contexts with Fastify and pool diagnostics. Fixed route templates include the principal POST query endpoints (READ); unlisted routes are OTHER, not raw paths. Fixed stages and sanitized resource/error categories preserve first-failure stage. Pool/admission rejection counters and bounded dropped-log counts are included. No SQL, binds, credentials, cookies, response body, error message/cause or actual parameterized URL is logged. Sink errors do not alter responses. This is process-local diagnostic correlation, not distributed tracing.

Adapter README now links current providers and distinguishes implemented sales/transfer/maintenance/HISTORY/query areas from retained historical slice notes and actual verification limits.
