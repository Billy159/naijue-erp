## Findings

- Migration 0008 defines exactly two replacements: validate_sparse_balance_commit and validate_transfer_effect. Only a schema-migration metadata INSERT accompanies them. It adds no relation, field, index, trigger or business data. Existing migrations 0001–0007 match HEAD without edits; their hashes are retained separately.
- The 0007 IMPORT baseline tail is text-identical, and its existing UPDATE behavior is unchanged except comments. The transfer source-validation prefix and exact reversal-validation tail are text-identical to 0004. Only its absent-balance branch permits an APPROVE with no reversal, a published exact key and no existing ledger.
- The first-use deferred INSERT branch requires the native runtime document, APPROVE receipt/audit identity, complete immutable final publication, no prior other-operation use, and exact current-operation/key cumulative quantity and actual effect count as final balance/version. The current operation is indexed by existing operation-prefix uniqueness; prior-used-key checks use the existing warehouse/SKU ledger index. There is no full historical SUM or all-SKU preload.
- Exact published-zero proof is obtained only for absent locked warehouse/SKU keys and belongs to the UOW's same acquired query client. It checks the immutable publication checkpoint/final approval, native capability guard/table pairs, exact membership, native size-group relationship with the exact membership row SHARE-locked, balance absence and prior-ledger absence. Proof caches are confined to one helper/UOW instance. Publication membership is not represented as authorization; services retain their existing trusted authorization/reference checks before proof/effects.
- Binary JSON tuple advisory order and inventory_key_lock namespace match the 0007 importer. Distinct actual posting keys are deduplicated before explicit awaited key locks, followed by one ordered existing-balance row-lock query. This closes the normal absent-key read gap at source/protocol level, not as live engine race evidence.
- Repeated actual same-SKU lines are not collapsed. The first genuine nonzero ledger effect precedes the version-1 actual-delta INSERT; later real effects update cumulative quantity/version using exact prior-version CAS. Actual cancellation to zero is retained as used stock. First-insert conflict/acknowledgement other than one row fails rather than upserting or updating cached state. Existing negative and retained-zero rows are not conflated with absence.
- Missing-balance UNAPPROVE and synthetic adapters without the explicit hook fail before their missing-key effect. Read/proof/draft/VOID do not materialize balance or zero ledger rows. Historical cutoff writes and post-publication catalogue CREATE coverage remain closed/outside scope.
- The service/UOW path keeps ledger, balance, header, audit and receipt in the same transaction. Existing actor/request-key serialization/replay, document locks/CAS, rollback requests, unknown-COMMIT handling and connection discard are retained. No source-only/scripted result is described as a live concurrency or durability pass.
