# Sales list number-filter source alignment

Frozen `frontend/sales-current.js:49` applies case-insensitive substring inclusion to the displayed document number using browser `toLocaleLowerCase().includes(...)`. The previous native number filter was literal but case-sensitive. This narrow delta aligns count/page predicates to `strpos(lower(h.number), lower($parameter)) > 0`. It keeps the original request text as one driver parameter and does not introduce LIKE/ILIKE patterns, SQL interpolation, extensions or locale settings. Percent, underscore and backslash remain literal characters.

The existing strict web response-membership validator now compares `number.toLowerCase().includes(filter.number.toLowerCase())`. JavaScript default Unicode lowercase is deterministic and does not depend on the viewer's browser locale. PostgreSQL `lower` depends on the database locale/collation; frozen browser locale casing, deterministic JavaScript default casing and PostgreSQL Unicode locale edge cases are not claimed to be identical. Real-engine verification of the intended deployment locale and Unicode edge cases is still required. ASCII case-insensitive literal matching is the confirmed shared behavior.

The shared number predicate also keeps statistics filtering consistent with the list.
