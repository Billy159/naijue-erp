# Unknown warehouse: separate source-review schema candidate

This is source work, not an installed persistence feature. No PostgreSQL process or connection was opened, no real source rows were read, and no platform settings, credentials, departments, warehouses, or ordinary sales permissions were changed. The generated candidate always raises `SOURCE_REVIEW_SCHEMA_SUCCESSOR_NOT_ADMITTED` immediately after BEGIN. It supplies no ungated patch/install/host route. The r2 source and the current hall/amount combined installer remain unchanged.

## What is implemented in source

- A distinct SOURCE_REVIEW protocol uses only the existing import_batch, import_record, audit_change and operation_receipt tables. It adds no tables or columns, changes 13 existing guard/validator bodies only by inserting a strict source-review branch, and declares 14 new routines. The projected routine count is 166, not the combined installer's 152.
- The command candidate stages a nonempty approved pending partition, retains exact externally SHA-bound UTF-8 approval bytes in immutable ordered base64 audit segments, captures exact distinct occurrences, and seals only after exact occurrence-set, count, group and no-effect closure. No pending row becomes an ordinary sales document, ledger entry, EXCLUDED row, zero stock, or zero amount.
- Each capture keeps raw strings/null/missing fields, original source keys (including blank orphan keys), original group evidence, file/sheet/row/occurrence identity and a distinct normalized representation. Repeated business keys are not collapsed. The deterministic UUID is an immutable capture ID, never an invented warehouse or hall.
- Original approval bytes and the exact serialized source-hash preimage are retained. The latter is hashed as original UTF-8 and separately compared to its parsed 15-item tuple. PostgreSQL jsonb text is never substituted for that source hash. Coordinate numbers such as JSON 1.0 and 1 are equivalent integer metadata and hash canonically; original cell strings such as "1.0" remain unchanged.
- SOURCE_REVIEW alone permits NULL cutoff. Both old inventory modes still require a nonnull cutoff. Capture timestamps remain database capture times, not original export/accounting times. Captures remain permanently QUARANTINED with NULL target/reviewed_at. Complete capture is PASSED/PENDING_REVIEW, never IMPORTED.
- Two SECURITY DEFINER APIs require the existing protected IMPORTER plus a live enabled current ADMIN. Helpers are private. New routines have fixed pg_catalog,naijue_erp,pg_temp search_path and UTC timezone; PUBLIC and the three interface roles lose default execute on all helpers, and only the two exact APIs receive IMPORTER execute in this candidate. No direct table grant is added.
- Four existing runtime policies are replaced, not supplemented. Review batches are excluded. Review child rows are allowed only through positive EXISTS of a visible non-review parent. IMPORT rows are isolated by their batch, independent of any claimed JSON profile. The original non-review business-ready predicate and WITH CHECK scope remain.
- The bounded authenticated read candidate pages import_record first and follows each exact operation/ordinal pointer. It reports durable pending versus expected-but-not-received counts and never joins current warehouse/staff data to relabel the source.

## Explicit limits and next gates

1. Only REVIEW_STAGE, REVIEW_APPROVAL, REVIEW_CAPTURE, REVIEW_SEAL and bounded read have candidate implementations. REVIEW_RESOLVE explicitly raises NOT_IMPLEMENTED. There is no fabricated successful decision, REVIEWED_READY state, materialization link or conversion proof. Resolution history and atomic consumption/publication require the separate successor described in the reviewed design.
2. This first wire accepts 1..250000 occurrences, unlike the broader design's future explicitly empty partition branch. It requires an already initialized ADMIN and an already published stock baseline. Fresh-bootstrap ready/pending partitioning is not implemented and must not be claimed complete.
3. The approved pending set can be conserved by this protocol. Complete original-package materialized-plus-pending census is not proved merely by an external approval or by this isolated set. Actual source-file reading and the fresh root-plan/partition successor remain separate gates.
4. The external SHA/namespace/file pins are validated by the separate application reader. The SQL API checks matching retained bytes, not the provenance of an arbitrary caller-supplied SHA. A trusted protected host admission and exact source capability remain mandatory and unimplemented. A hash by itself is not authorization.
5. Each future command must use its own isolated top-level transaction, with no SAVEPOINT or PL/pgSQL EXCEPTION subtransaction. The current-XID proof deliberately fails closed for unsupported subtransactions; it has not been relaxed to accept another in-progress transaction. The candidate changes only 16 named inherited constraints/triggers, not SET CONSTRAINTS ALL or another schema's constraints.
6. The source compiler's owner/table/routine/body assertions are not a full catalog-admission proof. Full resulting function definitions/owner/config/ACL, every effective RLS policy, table RLS flags, all grants/default grants/role memberships and attached triggers need independent comparison on a specifically authorized disposable synthetic engine before an executable successor may be admitted.
7. No PostgreSQL parser or engine test has run here. Reconnect/readback, failed-chunk rollback, retry/conflict behavior, anonymous/runtime/SALESPERSON denial after publication, direct DML refusal, top-level/subtransaction behavior, concurrent locks, no-effect verification and ordinary regression are all engine gates, not passed tests. Generated SQL and JavaScript source tests do not establish them.
8. The final dedicated SQL-review report was not obtained. Earlier findings and their corrections are recorded, but they are not a final independent sign-off of the last source revision. The exact failure and missing scope are retained in independent-review-status.json. That reporting step was stopped without retry or a replacement route.
